# 首页设计文档

## 一、设计定位

首页承担三项核心职责：

1. **系统就绪状态检测** — 在用户操作前，确保 Neo4j、后端服务等基础设施处于可用状态。
2. **文档上传入口** — 提供文件上传通道，进入后续的图谱构建流程。
3. **项目列表管理** — 展示已有项目，提供查看、删除等快捷操作。

## 三、分阶段交互流程

### 阶段一：系统就绪检测（系统首次加载时自动触发）

**目标**：在用户进行任何操作前，确保后端服务和 Neo4j 可用。

| 步骤 | 交互 | 后端动作 | 前端状态变化 |
|------|------|----------|-------------|
| 1.1 | 页面挂载完成 | — | 显示 loading spinner，覆盖整个首屏 |
| 1.2 | 自动调用 `GET /api/health` | 返回 `{neo4j, backend, llm}` 状态 | — |
| 1.3 | 所有服务正常 | — | 隐藏 spinner，显示就绪状态卡片（绿色勾选） |
| 1.4 | 任一服务异常 | 返回错误信息 | 显示警告卡片（黄色/红色），显示具体异常项，[Start] 按钮禁用 |

**就绪状态卡片 UI**：
- 三个状态项横向排列：Neo4j 连接 / 后端服务 / LLM 模型
- 每项显示图标（✅ 正常 / ❌ 异常 / ⏳ 检测中）+ 简要说明
- 检测通过后整体卡片边框变为浅绿色背景

**异常状态卡片 UI**：
- 卡片标题变为"系统状态异常"
- 异常项高亮显示
- 底部提示："请检查服务配置后刷新页面"
- [Start] 按钮置灰 + tooltip 提示原因

---

### 阶段二：文件上传与图谱构建（点击 Start 后）

**目标**：引导用户上传文档并启动图谱构建任务。

| 步骤 | 交互 | 后端动作 | 前端状态变化 |
|------|------|----------|-------------|
| 2.1 | 点击 [Start / 立即开始] | — | 路由跳转到 `MainView` |
| 2.2 | MainView 中显示上传区域 | — | 显示拖拽上传区域 |
| 2.3 | 用户拖拽或选择文件 | — | 文件列表显示文件名、大小、类型 |
| 2.4 | 点击 [开始构建图谱] | `POST /api/graph/build` 创建任务 | 跳转到 MainView 的任务进度面板 |
| 2.5 | 轮询 `GET /api/graph/task/{id}` | 返回进度百分比、当前阶段、节点数 | 进度条实时更新，显示阶段说明 |
| 2.6 | 任务完成 | 返回 `{status: "Completed"}` | 显示"构建完成"提示，节点数统计，[查看图谱] 按钮 |

**上传区域 UI**：
- 支持拖拽上传和点击选择两种方式
- 显示支持的文件类型：PDF、TXT、MD
- 上传过程显示上传进度条
- 支持批量上传多个文件

**任务进度面板 UI**（在 MainView 中）：
- 顶部进度条（百分比 + 颜色变化：蓝→绿）
- 当前阶段文字说明：
  - "正在解析文档..."（0-20%）
  - "正在提取实体..."（20-60%）
  - "正在建立关系..."（60-85%）
  - "正在保存到图谱..."（85-100%）
- 实时统计：已提取节点数、关系数、当前处理文件
- [取消] 按钮（用户可中途停止）
- 完成后显示节点统计卡片（总节点数、关系数、文档数）

---

### 阶段三：项目管理与跳转

**目标**：在首页展示历史项目列表，支持快捷操作。

| 步骤 | 交互 | 后端动作 | 前端状态变化 |
|------|------|----------|-------------|
| 3.1 | 页面加载时 | `GET /api/projects` 或 `GET /api/graph/projects` | 加载最近 10 个项目 |
| 3.2 | 显示项目列表 | — | 卡片式列表展示 |
| 3.3 | 点击项目卡片 | — | 路由跳转到 `MainView?projectId=xxx` |
| 3.4 | 点击 [删除] | `DELETE /api/graph/project/{id}` | 列表中移除该项，显示确认提示 |
| 3.5 | 项目数为空 | — | 显示空状态插画 + "还没有项目，开始构建你的第一个图谱吧" |

**项目卡片 UI**：
- 项目名称（可编辑）
- 关联文档数（文件图标 + 数字）
- 节点总数（圆点图标 + 数字）
- 创建时间（相对时间："3 天前"）
- 操作按钮：[查看图谱] [删除]
- Hover 时整体卡片轻微上浮 + 阴影加深

## 四、关键交互细节

### 4.1 系统状态检测

```javascript
// 前端调用链
onMounted(async () => {
  await checkSystemStatus()
  if (allHealthy) {
    await loadProjects()
  }
})
```

- 检测为**一次性动作**，页面刷新时才重新检测
- 成功后不重复请求

### 4.2 Start 按钮行为

- 系统就绪时：主按钮，蓝色背景，白色文字
- 系统异常时：置灰，显示 tooltip 说明原因
- 点击后：路由跳转至 MainView

### 4.3 上传区域交互

- 拖拽进入时：边框颜色变为蓝色虚线，背景变为浅蓝色
- 拖拽离开时：恢复原状
- 上传失败：红色边框，显示错误信息
- 上传成功：绿色勾选，自动收起上传区域

### 4.4 项目删除确认

- 点击删除后：弹出确认对话框（"确定删除项目 '{name}'？删除后将无法恢复。"）
- 确认后：删除按钮变为 loading 状态
- 删除成功后：列表动画移除该项

## 五、状态变量清单

| 变量名 | 类型 | 描述 |
|--------|------|------|
| `systemStatus` | `ref<{neo4j, backend, llm}>` | 三项系统服务的就绪状态 |
| `isChecking` | `ref<boolean>` | 是否正在检测系统状态 |
| `projects` | `ref<Project[]>` | 项目列表数据 |
| `isLoadingProjects` | `ref<boolean>` | 项目列表加载中 |
| `isAllHealthy` | `computed<boolean>` | 三项服务全部就绪 |
| `hasWarning` | `computed<boolean>` | 存在任一服务异常 |

## 六、样式规范

- **主色调**：蓝色 `#409EFF`（Element Plus 默认蓝）
- **成功色**：绿色 `#67C23A`
- **警告色**：橙色 `#E6A23C`
- **危险色**：红色 `#F56C6C`
- **背景色**：浅灰 `#F5F7FA`
- **卡片圆角**：8px
- **卡片阴影**：`0 2px 12px rgba(0, 0, 0, 0.1)`
- **Hover 上浮**：`transform: translateY(-2px)` + 阴影加深

---

## 七、与其他页面的关系

```
HomeView
  ├── System Status → 全局共享状态（影响整个应用可用性）
  ├── [Start] → MainView（上传 + 构建 + 交互）
  └── Project List → MainView（加载已有项目）
```

- HomeView 是整个应用的入口页面
- 所有后续操作（上传、图谱交互、项目管理）均通过 MainView 完成
- HomeView 不维护持久状态，系统状态检测为会话级
